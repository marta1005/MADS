CTA/BWB MADS Environment Requirements
=====================================

1. Required System Tools
------------------------

A working installation needs:

  Python 3.11
  C/C++ compiler
  Fortran compiler, e.g. gfortran
  CMake
  Git
  BLAS/LAPACK implementation, e.g. OpenBLAS, MKL or system BLAS
  HDF5 development libraries
  CGNS development libraries, required by DUST builds using CGNS
  MPI implementation if mpi4py or the local DUST build requires it

The following commands should be available or loaded through modules:

  python
  python3.11-config
  pip
  cmake
  git
  gfortran


2. Python Virtual Environment
-----------------------------

Create and activate a Python 3.11 environment:

  python3.11 -m venv <VENV_DIR>
  source <VENV_DIR>/bin/activate
  python -m pip install --upgrade pip setuptools wheel

Use this environment consistently for MADS, pyGeo, pyspline and GEMSEO.

    numpy==2.3.3 scipy==1.15.2 pandas==2.3.2 matplotlib==3.10.6 \

4. pyGeo and pySpline
---------------------

pyGeo is required for IGES export. pyspline is required by pyGeo and must be
compiled with its native Fortran extension so that `pyspline/libspline.*` is
available in the active Python environment.

Install pyGeo from source:

  python -m pip install "git+https://github.com/mdolab/pygeo.git"

For pyspline, do not rely on a pure Python install if it does not provide
`libspline`. A broken pyspline installation commonly fails with:

  ImportError: cannot import name 'libspline' from partially initialized module 'pyspline'

Generic pyspline build procedure:

  git clone https://github.com/mdolab/pyspline.git <PYSPLINE_SRC>
  cd <PYSPLINE_SRC>
  cp config/defaults/<MATCHING_CONFIG_FILE>.mk config/config.mk

Edit `config/config.mk` so that it points to the active environment:

  PYTHON        = <VENV_DIR>/bin/python
  PYTHON-CONFIG = <PATH_TO_PYTHON_3_11_CONFIG>
  F2PY          = <VENV_DIR>/bin/f2py

Then build and install:

  make
  python -m pip install --force-reinstall --no-deps --no-build-isolation <PYSPLINE_SRC>

Validation:

  python -c "from pyspline import Curve, Surface, Volume, libspline; from pygeo import pyGeo; print('pyGeo/pyspline OK')"

If this fails on HPC, ask the system administrator to compile pyspline for the
same Python environment used by MADS.


5. DUST
-------

DUST is not a Python package. It must be compiled separately and made available
through PATH or through the `--dust-bin-dir` argument used by
`examples/cta_dust_doe.py`.

Required DUST executables:

  dust_pre
  dust
  dust_post

Generic DUST build outline:

  git clone https://public.gitlab.polimi.it/DAER/dust.git <DUST_SRC>
  cmake \
    -S <DUST_SRC> \
    -B <DUST_SRC>/build \
    -DCMAKE_BUILD_TYPE=Release \
    -DWITH_PRECICE=NO \
    -DCMAKE_INSTALL_PREFIX=<DUST_INSTALL_DIR> \
    -DCMAKE_PREFIX_PATH=<BLAS_OR_SITE_PREFIX> \
    -DCGNS_INC=<CGNS_INCLUDE_DIR> \
    -DCGNS_LIB=<CGNS_LIBRARY_DIR>
  cmake --build <DUST_SRC>/build --parallel <N_CORES>
  cmake --install <DUST_SRC>/build

After installation, either add DUST to PATH:

  export PATH=<DUST_INSTALL_DIR>/bin:$PATH

or define the MADS-specific DUST executable directory:

  export MADS_DUST_BIN_DIR=<DUST_INSTALL_DIR>/bin

or pass the install directory explicitly:

  python <MADS_ROOT>/examples/cta_dust_doe.py --dust-bin-dir <DUST_INSTALL_DIR>/bin ...

Validation:

  command -v dust_pre
  command -v dust
  command -v dust_post

DUST normally reads input files from the current working directory, so `dust`,
`dust_pre` and `dust_post` may print an input-file error if called without a
valid DUST case. That still confirms the executable is callable.


6. MADS Runtime Environment
---------------------------

When running examples from a separate BWB working directory, define:

  export PYTHONDONTWRITEBYTECODE=1
  export MPLCONFIGDIR=<WRITABLE_TEMP_MPL_DIR>
  export PYTHONPATH=<MADS_ROOT>/src:<MADS_ROOT>/examples
  export MADS_DUST_BIN_DIR=<DUST_INSTALL_DIR>/bin

For convenience, MADS also provides a shell helper. From the MADS repository
root, source it so that the variables remain in the current terminal:

  source scripts/setup_cta_env.sh <DUST_INSTALL_DIR>/bin [EXTRA_LIBRARY_DIR ...]

This sets `MADS_ROOT`, `PYTHONDONTWRITEBYTECODE`, `MPLCONFIGDIR`,
`PYTHONPATH`, `MADS_DUST_BIN_DIR`, and a serial-safe `I_MPI_FABRICS=shm`
default for local geometry/DUST checks. It also prepends
`<DUST_INSTALL_DIR>/lib` to `LD_LIBRARY_PATH` when that directory exists. Extra
library directories can be passed after the DUST bin directory, for example:

  source scripts/setup_cta_env.sh <DUST_INSTALL_DIR>/bin <HDF5_INSTALL_DIR>/lib

If DUST is already in PATH, the DUST argument can be omitted:

  source scripts/setup_cta_env.sh

If DUST starts but fails with a missing shared library such as
`libhdf5.so.310`, find the HDF5 library directory and either pass it as an
extra argument or export it manually:

  export LD_LIBRARY_PATH=<HDF5_INSTALL_DIR>/lib:$LD_LIBRARY_PATH

Recommended placeholders:

  <MADS_ROOT>                path to the MADS repository
  <BWB_ROOT>                 path to the BWB repository or working directory
  <VENV_DIR>                 active Python 3.11 virtual environment
  <WRITABLE_TEMP_MPL_DIR>    writable temporary Matplotlib cache directory
  <DUST_INSTALL_DIR>         DUST installation prefix


7. Workflow Validation Commands
-------------------------------

Validate MADS CTA imports:

  PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR=<WRITABLE_TEMP_MPL_DIR> \
  PYTHONPATH=<MADS_ROOT>/src:<MADS_ROOT>/examples \
  <VENV_DIR>/bin/python -c "import cta_geometry; import cta_dust_doe; print('MADS CTA imports OK')"

Generate CTA geometry and IGES:

  PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR=<WRITABLE_TEMP_MPL_DIR> \
  PYTHONPATH=<MADS_ROOT>/src:<MADS_ROOT>/examples \
  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_geometry.py

Run CTA + DUST-VLM baseline at AoA = 3 deg, 150 time steps:

  PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR=<WRITABLE_TEMP_MPL_DIR> \
  PYTHONPATH=<MADS_ROOT>/src:<MADS_ROOT>/examples \
  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_dust_doe.py \
    --baseline-only \
    --dust-method vlm \
    --alpha-deg 3.0 \
    --n-steps 150 \
    --mesh-span-stations 21 \
    --mesh-chord-stations 21 \
    --dust-bin-dir <DUST_INSTALL_DIR>/bin \
    --no-vtk \
    --output-dir <MADS_ROOT>/outputs/CTA_case/datasets/baseline_vlm_150_aoa03

Generate a fixed DOE sample table for a campaign:

  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_dust_doe.py \
    --generate-samples-only \
    --sample-method sobol \
    --n-samples 5000 \
    --sample-seed 17 \
    --samples-csv <MADS_ROOT>/outputs/CTA_case/datasets/campaign_001_exploration/samples/cta_dust_vlm_samples.csv

Run a serial shard of 50 samples from that table:

  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_dust_doe.py \
    --samples-csv <MADS_ROOT>/outputs/CTA_case/datasets/campaign_001_exploration/samples/cta_dust_vlm_samples.csv \
    --sample-start 0 \
    --sample-count 50 \
    --dust-method vlm \
    --alpha-deg 3.0 \
    --n-steps 150 \
    --mesh-span-stations 21 \
    --mesh-chord-stations 21 \
    --n-threads 1 \
    --dust-bin-dir <DUST_INSTALL_DIR>/bin \
    --no-vtk \
    --output-dir <MADS_ROOT>/outputs/CTA_case/datasets/campaign_001_exploration/shards/shard_00000

Run the same campaign with SLURM arrays:

  cd <MADS_ROOT>
  mkdir -p outputs/CTA_case/datasets/slurm_logs
  export DUST_BIN_DIR=<DUST_INSTALL_DIR>/bin
  export DUST_LIB_DIR=<OPTIONAL_EXTRA_DUST_OR_HDF5_LIB_DIR>
  export VENV_DIR=<VENV_DIR>
  export SAMPLES_CSV=outputs/CTA_case/datasets/campaign_001_exploration/samples/cta_dust_vlm_samples.csv
  export CAMPAIGN_ROOT=outputs/CTA_case/datasets/campaign_001_exploration
  export CASES_PER_WORKER=50
  export DUST_THREADS=1
  export N_STEPS=150
  sbatch --array=0-99 scripts/slurm_cta_dust_vlm_shards.sh

Merge finished shards into one flat CSV:

  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_merge_dust_shards.py \
    --campaign-root <MADS_ROOT>/outputs/CTA_case/datasets/campaign_001_exploration

Run the VLM convergence study used for the current CTA screening workflow:

  PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR=<WRITABLE_TEMP_MPL_DIR> \
  PYTHONPATH=<MADS_ROOT>/src:<MADS_ROOT>/examples \
  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_dust_vlm_convergence.py \
    --dust-bin-dir <DUST_INSTALL_DIR>/bin

The panel convergence script is retained for high-fidelity checks, but it is
too expensive for the 150-sample screening campaign:

  PYTHONDONTWRITEBYTECODE=1 MPLCONFIGDIR=<WRITABLE_TEMP_MPL_DIR> \
  PYTHONPATH=<MADS_ROOT>/src:<MADS_ROOT>/examples \
  <VENV_DIR>/bin/python <MADS_ROOT>/examples/cta_dust_panel_convergence.py \
    --dust-bin-dir <DUST_INSTALL_DIR>/bin

The lifting-line script is a diagnostic only for this CTA/BWB geometry. It
requires airfoil polar data, but even with NeuralFoil-generated polars the
full centerbody geometry is not a good lifting-line model.
